# M2 — Storage — Implementation Plan

> Build task by task, test first. Each task ends green (`npm test`, `npm run lint`, `npx tsc --noEmit`) and with one conventional commit.

**Goal:** Every answer is stored in Supabase (Zurich) the moment the participant presses OK, through four route handlers that only the server can call the database from. A refresh resumes from the server; the thank-you screen shows a reference code; `npm run export` writes the data to `data/`; a daily cron keeps the project awake, exports, and deletes unfinished responses older than seven days.

**Architecture:** The browser talks only to our own `/api/*` routes (same origin, JSON). The routes validate with Zod, apply the same `applyAnswer` rule as the browser, and call one module, `src/db.ts`, which is the only place that holds a Supabase client. The database accepts nothing from the public roles: tables are granted to `service_role` only, RLS is on with no policies, and the one write that must be atomic (store an answer and delete what it skips) is a Postgres function.

**Spec:** design §7 (data model), §8 (API and the answer rule), §10 (security), §11 (operations), §12 (route tests). `IMPLEMENTATION.md` §4 M2 acceptance criteria.

### Task 1: Schema migration

**Files:** create `supabase/migrations/20260922000000_initial_schema.sql`.

The SQL (design §7, plus grants and the function):

```sql
-- Initial schema: responses, answers, probe_calls. Only the server (service_role,
-- via the secret key) may touch these tables; the public roles get nothing.

create table public.responses (
  id            uuid primary key default gen_random_uuid(),
  company_uid   text check (char_length(company_uid) <= 32),
  probe_allowed boolean not null default false,
  lang          text not null check (lang in ('de', 'en')),
  form_version  text not null,
  consented_at  timestamptz not null,
  completed_at  timestamptz,
  created_at    timestamptz not null default now()
);

create table public.answers (
  id             uuid primary key default gen_random_uuid(),
  response_id    uuid not null references public.responses(id) on delete cascade,
  question_id    text not null,
  followup_index smallint not null default 0 check (followup_index between 0 and 2),
  question_text  text not null,
  value          jsonb not null,
  created_at     timestamptz not null default now(),
  unique (response_id, question_id, followup_index)
);

create table public.probe_calls (
  id             bigint generated always as identity primary key,
  response_id    uuid not null references public.responses(id) on delete cascade,
  question_id    text not null,
  followup_index smallint not null,
  model          text not null,
  prompt_version text not null,
  decision       text not null check (decision in ('ask', 'stop', 'error', 'rejected')),
  reason         text,
  error_class    text,
  input_tokens   int,
  output_tokens  int,
  latency_ms     int,
  created_at     timestamptz not null default now()
);

create index probe_calls_response_id_idx on public.probe_calls (response_id);
create index responses_unfinished_idx on public.responses (created_at) where completed_at is null;

alter table public.responses   enable row level security;
alter table public.answers     enable row level security;
alter table public.probe_calls enable row level security;
-- no policies: service_role bypasses RLS; nobody else has a grant

revoke all on public.responses, public.answers, public.probe_calls from anon, authenticated;
grant select, insert, update, delete on public.responses, public.answers to service_role;
grant select, insert, delete on public.probe_calls to service_role;

-- Stores one answer and deletes the answers it made obsolete, in one
-- transaction. Refuses a response that does not exist or is completed.
create function public.save_answer(
  p_response_id    uuid,
  p_question_id    text,
  p_followup_index smallint,
  p_question_text  text,
  p_value          jsonb,
  p_pruned         text[]
) returns boolean
language plpgsql
security invoker
set search_path = ''
as $$
begin
  if not exists (
    select 1 from public.responses
    where id = p_response_id and completed_at is null
  ) then
    return false;
  end if;

  insert into public.answers (response_id, question_id, followup_index, question_text, value)
  values (p_response_id, p_question_id, p_followup_index, p_question_text, p_value)
  on conflict (response_id, question_id, followup_index)
  do update set question_text = excluded.question_text, value = excluded.value;

  delete from public.answers
  where response_id = p_response_id and question_id = any (p_pruned);

  return true;
end;
$$;

revoke execute on function public.save_answer from public, anon, authenticated;
grant execute on function public.save_answer to service_role;
```

### Task 2: Environment and the database module

**Files:** `.env.example`, `src/env.ts`, `src/db.ts`; tests `tests/env.test.ts`.

- `.env.example`: `SUPABASE_URL=`, `SUPABASE_SECRET_KEY=`, `CRON_SECRET=`, `BLOB_READ_WRITE_TOKEN=` (the last optional in M2). Koray copies the secret key from the dashboard (Settings → API Keys) into `.env.local`; it never appears in chat or git.
- `src/env.ts`: `serverEnv()` parses `process.env` with Zod (`SUPABASE_URL` a URL, `SUPABASE_SECRET_KEY` starting with `sb_secret_`, `CRON_SECRET` ≥ 32 characters) and throws a clear message naming the missing variable — never its value. Tested.
- `src/db.ts`: `createClient(url, secretKey, { auth: { persistSession: false } })`, created lazily. Functions, each a few lines: `createResponse`, `getResponse` (with its fixed answers), `saveAnswer` (calls `rpc("save_answer")`), `completeResponse`, `deleteUnfinishedBefore(date)`, `touch()` (the keep-alive read). Not unit-tested against the network; the routes' tests mock this module, and Task 9 checks it end to end.
- Install `@supabase/supabase-js` with a pinned version; lockfile committed.

### Task 3: Request guard

**Files:** `src/http.ts`; test `tests/http.test.ts`.

`readJson(request, schema)` returns `{ ok: true, data }` or `{ ok: false, response }`:
- `Sec-Fetch-Site` present and not `same-origin`/`none` → 403.
- `Content-Length` or actual body over 16 kB → 413.
- Not JSON or not matching the Zod schema → 400 with a short message (no echo of the input).
Plus `json(status, body)` and an `isUuid` check. Tests cover each branch.

### Task 4: Create and resume

**Files:** `src/app/api/responses/route.ts`, `src/app/api/responses/[id]/route.ts`; tests in `tests/api/`.

- `POST /api/responses` body `{ c?: string, lang: "de"|"en", consent: true }` → 201 `{ id, probeAllowed: false }`. `consent` must be literally `true` (otherwise 400). `c` trimmed, max 32 characters, stored as given.
- `GET /api/responses/:id` → `{ lang, formVersion, completed, answered: [{ questionId, followupIndex, questionText, value }] }`; 404 for an unknown or malformed id.
- Tests (db mocked): consent missing → 400; cross-site request → 403; created row gets `form_version = FORM_VERSION`; resume returns answers; unknown id → 404.

### Task 5: Save an answer

**Files:** `src/app/api/responses/[id]/answers/route.ts`; test.

`POST` body `{ questionId, followupIndex: 0, value }` (follow-ups arrive in M3):
1. Parse with Zod (`AnswerValueSchema`), check the question exists in `FORM`.
2. Load the response; 404 if missing, 409 if completed.
3. Rebuild the current fixed answers, `validate` the value for the response's language (400 with the message), run `applyAnswer`, compute `pruned` = question ids present before and absent after (excluding this one).
4. Unchanged value (deep-equal to the stored one) and nothing pruned → 200 without a write.
5. Otherwise `saveAnswer(...)` with `question_text` taken from `FORM` in the response's language — never from the request.
6. Reply `{ followUp: null }` (M3 fills it).

Tests: duplicate POST → one `saveAnswer` call per distinct value; completed → 409; invalid value → 400; `relations` changed to `none` → `pruned` contains `case` and `duration`; question text comes from the form; opted-out e-mail is not stored (`cleanAnswer`).

### Task 6: Complete

**Files:** `src/app/api/responses/[id]/complete/route.ts`; test.

Refuses (409) unless every active question has an answer. Sets `completed_at` once (a second call returns the same code). Replies `{ referenceCode }` = first 8 hex characters of the id.

### Task 7: The form uses the server

**Files:** `src/api.ts`, `src/storage.ts`, `src/components/Form.tsx`, `src/components/ThankYou.tsx`, `src/app/page.tsx`, `src/texts.ts`; tests updated.

- `page.tsx` reads `?c=` and passes it to `Form`.
- Start → `POST /api/responses`; the id goes to localStorage. Each OK → `POST …/answers` (button shows it is saving; on failure a clear error and the answer stays on screen). The last OK → `POST …/complete`, then the thank-you screen with the reference code and the contact address; when a conversation was accepted, "I will be in touch by e-mail."
- On load with a stored id → `GET` and resume; 404 → start over quietly.
- `src/api.ts` retries a `POST` once on a network error (safe: the server upserts).
- Form tests mock `@/api` with a small in-memory fake built on the engine; the existing nine Form tests keep passing, plus: resume from server, save failure shows an error and keeps the answer, reference code shown.
