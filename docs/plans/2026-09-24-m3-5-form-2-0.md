# M3.5 — Form 2.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> Build task by task, test first. Each task ends green (`npm test`, `npm run lint`, `npx tsc --noEmit`) and with one conventional commit. Model behaviour is tested only by the opt-in evals (`RUN_LLM_EVALS=1`).

**Goal:** Replace the eight-screen form 1.0 with the fourteen-screen form 2.0 approved on 2026-09-23 (issue #15): a stacked-rows question type, a one-tap escape on `case`, two skip rules, several exclusive options on one question, the new welcome screen, and the version-2 probe prompts with their evals.

**Architecture:** The form stays data in `src/form.ts`; the engine (`src/engine.ts`) learns the new shapes, and the browser and the server keep calling the same engine functions, so they cannot disagree. Two new answer shapes enter the system: `{ rows: { rowId: scaleId } }` for the rows question and `{ option: "none" }` for the escape on an open question. The escape is never sent to the model, and an escaped case is never given to `pains` as context. The database needs no migration (design §17).

**Tech Stack:** Next.js 16 App Router, React, TypeScript, Zod 4, Vitest + Testing Library, AI SDK 7 (evals only).

**Spec:** `docs/design/2026-09-23-form-2.0.md` (texts, order, rules, reasoning) and issue #15 (task list, decisions, acceptance). The version-2 prompts are `docs/design/prompts-2.0/probe-{case,pains,gains}.md` until Task 4 moves them.

## Global Constraints

- `FORM_VERSION = "2.0.0"`.
- Question ids are permanent: `role`, `size`, `duration`, `pains`, `gains`, `followup` keep their ids; `relations` is retired, not renamed; new ids are `customers`, `case` (kept), `cost`, `result`, `activities`, `who`, `skipped`, `sources`.
- German and English texts are copied verbatim from design doc §3. `Sie`, Swiss spelling (`ss`, never `ß`), "Firma" not "Unternehmen".
- Open answers capped at 4,000 characters; at most two model calls per probed question.
- Skip rules: `case` escaped → skip `duration`, `cost`, `result`, `gains`; every `activities` row "never" → skip `sources`.
- Exclusive options: `cost` "no" and "don't know"; `skipped` "none"; `followup` "neither".
- Nothing on the welcome screen names a processor (Anthropic, Vercel, Supabase).
- No participant text anywhere in git; eval fixtures use fictional companies only.
- Commits: conventional, English, subject ≤ 60 characters, ending with the `Co-Authored-By` trailer.

## Decisions taken for M3.5 (2026-09-24, technical, for Koray's review)

| Decision | Choice | Why |
|---|---|---|
| Escape answer | `{ option: "none" }` on the open question, declared as `escape: Option` in `form.ts` | Reuses the existing `{ option }` shape, so the existing skip rule `{ question: "case", is: "none" }` works unchanged. |
| Rows answer | `{ rows: { [rowId]: scaleId } }` | One answer per question, as everywhere else; one row in `answers`. |
| "All never" rule | New skip condition `{ question, every: "never" }` beside `{ question, is }` | `is` already means "any value is"; `every` means "at least one value, and all of them are". |
| Exclusive options | `exclusive?: string[]` instead of one string | `cost` has two ("no", "don't know"). |
| `question_text` for rows | The stem only ("How often did this happen …"), like option labels today | Row and scale labels are versioned in `form.ts`; Task 7 puts the form itself into the export so the ids can be read back. |
| Escape in the UI | A text button under the answer box; one tap stores the escape and moves on | As quick as a choice; Back returns to an empty box with the escape marked, and typing a case un-skips the four questions. |
| Rows keyboard | No letter keys on the rows screen; Tab and Space choose, Enter submits | Five rows × five points make letter keys ambiguous. |
| Validation | `validate` now checks the answer's shape per question type and that every option id exists | The server must refuse `{ rows }` for `case`, an unknown scale point, or an escape where none is offered. |
| `sameAnswer` | Compares nested objects key-order-independently | Postgres `jsonb` reorders the keys inside `rows`; without this an unchanged rows answer is rewritten on every OK after Back. |
| Existing eval fixtures | Three flip from `stop` to `ask`, two answers are rewritten (Task 8) | The version-2 prompts also ask for the secondary element; see Task 8 for each one. |
| Test rows in Zurich | Deleted at the end of the milestone, only on Koray's explicit go | Destructive; three of Koray's own runs are there, plus whatever Task 9 writes. |

```ts
/** Whether the answer is the open question's escape, the one-tap "I can't think of such a case". */
export function isEscape(question: Question, value: AnswerValue | undefined): boolean {
  return (
    question.type === "open" &&
    question.escape !== undefined &&
    value !== undefined &&
    "option" in value &&
    value.option === question.escape.id
  );
}

const known = (options: Option[], id: string | undefined): boolean => options.some((option) => option.id === id);

const EMAIL = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;

/**
 * Null when the answer is acceptable, otherwise the message to show. Checks the
 * shape the question type expects and that every id is one the question
 * offers: the server runs this on whatever a request carries.
 */
export function validate(question: Question, value: AnswerValue, lang: Lang): string | null {
  if (question.type === "open") {
    if (isEscape(question, value)) return null;
    const text = "text" in value ? value.text.trim() : "";
    if (text.length === 0) return t(UI.required, lang);
    if (text.length > question.maxChars) return t(UI.tooLong, lang);
    return null;
  }
  if (question.type === "single") {
    return "option" in value && known(question.options, value.option) ? null : t(UI.chooseOne, lang);
  }
  if (!("options" in value) || value.options.length === 0) return t(UI.chooseOne, lang);
  const picked = value.options;
  if (!picked.every((id) => known(question.options, id))) return t(UI.chooseOne, lang);
  if (new Set(picked).size !== picked.length) return t(UI.chooseOne, lang);
  const exclusive = question.exclusive ?? [];
  if (picked.length > 1 && picked.some((id) => exclusive.includes(id))) return t(UI.chooseOne, lang);
  if (wantsEmail(question, picked)) {
    const email = (value.email ?? "").trim();
    if (email.length === 0) return t(UI.emailRequired, lang);
    if (!EMAIL.test(email)) return t(UI.emailInvalid, lang);
  }
  return null;
}
```

```ts
/**
 * Several statements answered on one shared scale. Each statement is its own
 * row with its own buttons, stacked, not a grid table (design §2). Answered as
 * { rows: { [rowId]: scaleId } }.
 */
export type RowsQuestion = {
  id: string;
  type: "rows";
  text: Text;
  help?: Text;
  rows: Option[];
  scale: Option[];
};

export type Question = SingleQuestion | MultiQuestion | OpenQuestion | RowsQuestion;

/**
 * A skip rule. `is`: the answer contains this option (for rows: some row has
 * it). `every`: the answer has at least one value and all of them are this one.
 * Both must name a question that comes before the ones they skip.
 */
export type Skip = {
  when: { question: string; is: string } | { question: string; every: string };
  skip: string[];
};
```

```ts
function chosen(value: AnswerValue | undefined): string[] {
  if (!value) return [];
  if ("option" in value) return [value.option];
  if ("options" in value) return value.options;
  if ("rows" in value) return Object.values(value.rows);
  return [];
}

/** Whether a skip rule's condition holds for the answers so far. */
function holds(when: Skip["when"], answers: Answers): boolean {
  const values = chosen(answers[when.question]);
  if ("is" in when) return values.includes(when.is);
  return values.length > 0 && values.every((value) => value === when.every);
}

export function isSkipped(form: Form, questionId: string, answers: Answers): boolean {
  return form.skips.some((rule) => rule.skip.includes(questionId) && holds(rule.when, answers));
}
```

```ts
    return Object.fromEntries(
      Object.entries(value)
        .sort(([x], [y]) => x.localeCompare(y))
        .map(([key, inner]) => [key, canonical(inner)]),
    );
  }
  return value;
}

/** Whether two answers are the same, whatever order their keys arrive in (jsonb reorders them). */
export function sameAnswer(a: AnswerValue, b: AnswerValue): boolean {
  return JSON.stringify(canonical(a)) === JSON.stringify(canonical(b));
}
```

```tsx
  async function submit() {
    if (busy) return; // one save at a time

    const problem = validate(question, value, lang);

    setBusy(false);
    setError(serverProblem ?? null);
  }
```

```ts
// A rough guess at the language of one short follow-up question, for the
// prompt evals: counts common German and English words. Good enough to catch
// a follow-up in the wrong language; not a language detector. Words that
// start or end with an umlaut are left out: JavaScript's \b does not see them.
import type { Lang } from "@/i18n";

const GERMAN = /\b(sie|ihnen|ihre?[mnrs]?|haben|hatten|hätten|welche[mnrs]?|wie|wo|wer|nicht|und|der|die|das|dabei|genau|bei)\b/gi;
const ENGLISH = /\b(you|your|what|how|which|where|who|whom|did|the|and|would|with)\b/gi;

export function languageOf(text: string): Lang | "unclear" {
  const german = text.match(GERMAN)?.length ?? 0;
  const english = text.match(ENGLISH)?.length ?? 0;
  if (german > english) return "de";
  if (english > german) return "en";
  return "unclear";
}
```
